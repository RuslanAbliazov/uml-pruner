PHASE 2: DEPTH-FIRST EXPLORATION (ADD ONE NODE AT A TIME!)

For EACH node in working graph (start with anchor):

┌─────────────────────────────────────────────────────────────────────────────┐
│ STEP 1: Preview ALL directions                                              │
└─────────────────────────────────────────────────────────────────────────────┘
   preview_neighbors(current_node, "both")
   → Returns: {outgoing: [...], incoming: [...]}

┌─────────────────────────────────────────────────────────────────────────────┐
│ STEP 2: Score neighbors by relevance (mental scoring)                       │
└─────────────────────────────────────────────────────────────────────────────┘

   For EACH neighbor, compute score:

   A. **Name matching** (most important):
      ✓ Contains query terms (exact/partial): +10 points
      ✓ Related domain words: +5 points
      ✓ JDK classes (java.*, javax.*): -100 points (skip!)
      ✓ Util/Helper without context: -5 points

   B. **Edge type priority**:
      ✓ Inheritance (base class/interface): +8 points
      ✓ Association (field/has-a): +6 points
      ✓ Dependency (parameter/uses): +3 points

   C. **Edge direction**:
      ✓ Incoming edge: +2 bonus (who uses this class? often important)
      ✓ Outgoing edge: +0 bonus

   D. **Context from current node**:
      ✓ If current node is MAIN class (high relevance to query):
         → Its neighbors likely important (+3 bonus)
      ✓ If current node is SUPPORTING:
         → Be more selective (+0 bonus)

┌─────────────────────────────────────────────────────────────────────────────┐
│ STEP 3: Pick TOP candidate                                                  │
└─────────────────────────────────────────────────────────────────────────────┘

   - Highest score ≥ 10? → Likely relevant, inspect details
   - Highest score 5-9? → Maybe relevant, inspect if unsure
   - Highest score < 5? → Probably irrelevant, skip (go to next node in graph)

┌─────────────────────────────────────────────────────────────────────────────┐
│ STEP 4: Inspect candidate (ONLY if score ≥ 5)                               │
└─────────────────────────────────────────────────────────────────────────────┘

   get_node_details([candidate_id])
   → Returns: {type, methods, params}

   **Compare with query**:
   - Methods mention query terms? (e.g., "getAddress", "setReadOnly")
   - Params/fields match query entities? (e.g., "AddressSet addresses")
   - Type relevant? (interface = abstraction, often useful)

   **Decision**:
   ✓ Clearly relevant → add_nodes([candidate_id]) → CONTINUE to STEP 1 with this node
   ✗ Not relevant → SKIP → Try next highest-scored neighbor
   ✗ No more candidates with score ≥ 5 → MOVE to next node in working graph

┌─────────────────────────────────────────────────────────────────────────────┐
│ STEP 5: Depth-first continuation                                            │
└─────────────────────────────────────────────────────────────────────────────┘

   - Only return to "parent" node when no relevant neighbors remain
